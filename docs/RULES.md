# MyHeritage Match Agent — правила

Полный текст правил проекта. Инструкции проекта на claude.ai держат каждое правило одной жирной строкой со ссылкой сюда (`§N`). `CLAUDE.md` держит правила, которые касаются только кода этого репозитория.

Каждое правило несёт дату и автора. Новое правило: одна строка в инструкциях проекта + полный текст здесь + запись в `wiki/log.md`.

---

## 1. Где что живёт

```
инструкции проекта (claude.ai)   КАК работать: одна жирная строка на правило, ≤ 10 000 знаков
        │
        ▼
docs/RULES.md (этот файл)        полный текст правил, без лимита
        │
        ▼
CLAUDE.md                        только то, что верно в этом репозитории
        │
        ├── docs/agent-method.md     ритуал старта, петля задачи, вики, автолог
        ├── wiki/                    знания: index · log · overview · concepts · entities · sources
        ├── .loops/                  уроки, запреты, неудачные попытки
        └── память проекта           ЧТО сейчас верно: индекс ≤ 12 КБ + файлы тем ≤ 4 КБ
```

| Слой | Хранит | Не хранит |
| --- | --- | --- |
| Инструкции проекта | правила поведения | факты, состояния |
| Память проекта (`MEMORY.md` + файлы тем) | текущие факты, решения владельца (Никиты), разрешения, открытые хвосты | правила из инструкций, длинные рецепты |
| `wiki/` | рецепты, история, разборы, грабли | секреты, почтовые адреса, временное состояние |
| Сырьё (`Context/`) | исходный текст как есть | (не правится) |
| Данные (`data/`, `logs/`) | сессия входа, граф, конфликты, логи | (локально, в git не идут) |

**Один факт — один дом.** Версия, путь, id, лимит живут в одном месте. Остальные места ссылаются. Меняешь факт: найди старое значение grep'ом и поправь все копии в том же ходе.

## 2. Порядок доверия, когда факты спорят

```
код / сайт / файл, проверенные в этой сессии
  >  сказал Никита
    >  агент видел на устройстве
      >  агент предположил
```

Внутри одной ступени побеждает более новая дата.

## 3. Жёсткие правила проекта

1. **Публиковать, удалять, отправлять — только после явного «да» в чате** (Никита, 2026-11-13). Сюда входят письма родственникам в MyHeritage, отклонение совпадений, удаление людей из дерева. Заранее данные разрешения записаны в памяти проекта.
2. **Пароли, токены, куки не вводить и не печатать** (2026-11-13). Вход в MyHeritage делает только Никита (`main.py --capture-session`); пароль сменён 2026-11-09.
3. **Капчу и WAF не обходить** (2026-10-18). Раннер уходит в паузу 6 ч; длинная серия капч лечится только свежим входом Никиты. Почему: три эпизода блоков, см. `wiki/concepts/captcha-and-waf.md`.
4. **Конфликтные генеалогические данные сами не сохранять** (2026-06-23). Разные имена, спорные даты, перестройка связей идут в очередь ручной проверки. Почему: целостность дерева важнее числа сохранений.
5. **Не больше 500 совпадений за сессию** (потолок поднят с 200 после 539 чистых прогонов; рабочий лимит 100 в `config.py`, см. `wiki/concepts/session-economics.md`). Почему: безопасность аккаунта.
6. **VIP-уведомление — только о прямых предках и только о новых находках** (2026-10-12). Без находок тишина. Почему: Никита хочет сигнал, а не шум.
7. **Один раннер на аккаунт: Mac Mini** (2026-11-03). Раннер на MacBook не включать. Работающий цикл менять в паузе между сессиями.
8. **Данные и сессии не коммитить** (2026-06-23): `data/` (сессия входа, `agent.db*`, `graph_updates.jsonl`, конфликты), `logs/`, `.env`, `recon/`. Добавлять файлы по одному.
9. **Селекторы не трогать, не прочитав `wiki/concepts/selectors.md`; после recon обновлять её** (2026-06-23). Почему: интерфейс MyHeritage меняется.
10. **Ответы родственникам в MyHeritage пишутся тепло и прямо, без канцелярита и тире-конструкций** (навык humanizer) и уходят только после «да» Никиты (§3.1).
11. **Все места давать кликабельной ссылкой** (`file://`, `smb://`, `http(s)://`) или путём от корня репозитория.

## 4. Сначала знания, потом вопрос

Перед задачей и перед вопросом ищи ответ в том, что проект уже знает. Спрашивать уже записанное нельзя.

1. Память проекта (загружается сама). Открой файл темы, а не только строку индекса.
2. `wiki/index.md` → нужные страницы; `wiki/log.md` (grep по теме).
3. `docs/`, `CLAUDE.md`, `Context/`.
4. Граф `graphify-out/GRAPH_REPORT.md`, если он есть.
5. Соседние треды проекта и общие файлы проекта (`notes/`).

Навык `mh-knowledge-lookup` делает локальный проход одной командой. В первом ответе одной строкой: что нашёл и где. Не нашёл — так и скажи, потом спрашивай.

После работы **запиши знание обратно**: страница вики → строка сверху в `wiki/log.md` → указатель в памяти проекта.

## 5. Замена решения — ритуал, а не тихая правка

1. Старая страница получает `status: superseded`, `superseded_by: <новая>`, дату.
2. Её тело сжимается до трёх строк: что поменялось и почему.
3. Новая страница несёт то же утверждение в новом виде.
4. В индексе старая строка уходит в раздел «Заменено».

## 6. Автопилот и когда спросить

Чёткую задачу доведи до проверенного результата сам: сделано → проверено перечитыванием ресурса (страница MyHeritage, файл, лог) → записано → сохранено. Потом отчёт.

**Остановись и спроси**, если действие:
- уходит наружу или его трудно откатить: письмо, отклонение совпадения, удаление из дерева;
- разрушает: удаление чужих файлов, force-push, переписывание истории;
- меняет общие устройства и сервисы (Mac Mini сверх выданного разрешения, NAS, аккаунт MyHeritage);
- касается другого проекта.

Никита разрешил автономную работу и планирование на Mac Mini (2026-11-02). На развилке, которая меняет цель, один вопрос с вариантами и рекомендацией. Мелочи решай сам и скажи, что выбрал.

## 7. Сохранение и секреты

- Никогда `git add -A` или `git add .`; добавлять файлы по одному; перед концом хода своя работа закоммичена и отправлена (`/ship`).
- Чужие несохранённые правки (например, `.obsidian/` на Mac) не трогать, сказать Никите.
- Секреты, пароли, куки, почтовые адреса аккаунтов не попадают в файлы проекта, вики и ответы. `tests/test_wiki.py` ловит очевидные случаи.
- `graphify-out/` — производный граф, в историю не идёт.

## 8. Самообучение

После задачи, которая заняла больше одной попытки или где Никита поправил: навык `mh-harness-reflect` → один урок с доказательством в `.loops/experience.md` или `NO_ENTRY`. Одна и та же ошибка дважды → запрет в `.loops/guardrails.md` (`/loop-guardrails`). Хук `Stop` напоминает об этом сам.
