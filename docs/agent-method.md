# Метод работы агента

Читать по требованию; правила — в [`RULES.md`](RULES.md). Ритуал старта и таблица авто-петель в [`CLAUDE.md`](../CLAUDE.md) главнее этого файла и подробнее его.

## 1. Ритуал старта (не пропускать)

1. `CLAUDE.md` — схема проекта.
2. Память проекта (`MEMORY.md`) — открыть файлы тем, которые касаются задачи.
3. Свежие записи журнала: `grep "^## \[" wiki/log.md | head -20`.
4. Запреты: `cat .loops/guardrails.md`.
5. Команды и навыки: `ls .claude/commands/ .claude/skills/`.
6. `git log --oneline -10`, `git status --short` (чужая несохранённая работа?), **на какой ветке живёт работающий раннер** (сейчас это ветка PR #1, а не `main`).
7. `wiki/index.md`, если вопрос про предметную область.

Нашёл готовое — сошлись на него в ответе.

## 2. Петля задачи

```
допущения → поиск готового (mh-knowledge-lookup, grep по проекту и wiki/) → план 2–5 шагов с проверкой
  → проба (_probe_*.py) → запуск → проверка ПЕРЕЧИТЫВАНИЕМ ресурса (не своему stdout)
  → убрать пробные скрипты → запись в wiki/log.md → сохранить (/ship) → отчёт
```

Отчёт — три вещи: что сделано (с фактами проверки), что осталось, на что смотреть в следующий раз.

**Второй раз делаешь то же самое — пиши скрипт или команду.** Первый раз хватит разового действия (`_probe_*.py`, удалить перед коммитом).

## 3. Вики

| Слой | Путь | Кто меняет |
| --- | --- | --- |
| Сырьё | `Context/` (бриф проекта) | никто |
| Вики | `wiki/` (кроме `wiki/people/`) | агент |
| Генерируемые страницы | `wiki/people/` | только `gedcom_to_obsidian.py` |
| Код | `browser/`, `auth/`, `storage/`, `scripts/`, `*.py` | агент, с проверкой |
| Данные | `data/`, `logs/` на Mac Mini | раннер; агент читает, в git не кладёт |
| Память | память проекта на claude.ai | агент и координатор |

Три операции:

1. **Ingest** — новое сырьё: страница `wiki/sources/<slug>.md`, правка затронутых `concepts/` и `entities/`, строка в `log.md`, строка в `index.md`.
2. **Query** — вопрос: сначала `index.md`, потом страницы; ответ со ссылками. Полезный ответ записать страницей.
3. **Lint** — по просьбе или раз в неделю: противоречия, устаревшее, сироты, пробелы. `python3 -m pytest -q tests/test_wiki.py` ловит механику (frontmatter, индекс, порядок журнала, ссылки, секреты).

### Формат страницы

```yaml
---
type: concept | source | entity
created: YYYY-MM-DD
updated: YYYY-MM-DD
sources: [<slug>, ...]          # откуда знание
# по желанию:
confidence: high | medium | low
status: active | superseded
superseded_by: <slug>
relates_to: [<slug>, ...]
staleness_window: 30d | 90d | 1y | none
tags: [...]
---
# Заголовок
```

Пересказывать, а не цитировать. Ссылаться на другие страницы относительными ссылками (`[selectors](selectors.md)`) или `[[slug]]`; оба вида проверяет тест.

### Журнал `wiki/log.md`

Только дополняется, **новое сверху**. Формат: `## [YYYY-MM-DD] ingest|query|lint|update|incident|feature|fix | заголовок`, потом поля `Object / Scenario / Outcome` и 1–5 строк. Хеш коммита вписать, когда он есть.

**Автолог:** каждая значимая операция → запись в журнал без просьбы. Сомневаешься, значима ли? Значит, да.

## 4. Граф (Graphify, по желанию)

Сейчас не используется: Graphify на машинах проекта не стоит. Если появится, `.githooks/post-commit` пересоберёт `graphify-out/` после коммита (включить: `git config core.hooksPath .githooks`). Граф в историю не идёт.

## 5. `/ship`

Одна команда для конца задачи: проверка изменений → запись в журнал → обновление индекса → тест вики → точечный stage → коммит → push → draft PR → отчёт. Текст — `.claude/commands/ship.md`.
